# Пакетная расшифровка звонков со смешанными языками

Инструкция для агента, отправляющего записи на распознавание.
Рассчитана на поток из сотен звонков на украинском, русском и польском.

## Доступ

**Эндпоинты:** `https://app.24print.ua:9443/detect-language` и `/asr`
POST, `multipart/form-data`, поле файла строго `audio_file`.
TLS валидный, `-k` не нужен.

**Авторизация:** заголовок `X-API-Key: <ключ>` (принимается и
`Authorization: Bearer <ключ>`). Без ключа — `401`. Ключ выдаётся владельцем
сервера, в репозитории его нет.

## Главное правило: группируй очередь по языку

Сервис держит в памяти модель выравнивания **только для одного языка на воркер**.
Смена языка = перезагрузка модели, 5–20 секунд. Это сделано намеренно: без
ограничения три языка на четырёх воркерах съедали ~28 ГБ и вытесняли из памяти
базу Bitrix, работающую на том же сервере.

Поэтому порядок работы — **сначала определить языки у всех звонков, потом
отсортировать по языку и расшифровывать группами**. При таком порядке
переключений будет два на весь прогон вместо сотен.

## Этап 1. Определение языка

Для каждого файла:

```bash
curl -X POST "https://app.24print.ua:9443/detect-language?encode=true" \
  -H "X-API-Key: $KEY" \
  -F "audio_file=@call.mp3;type=audio/mpeg" \
  --max-time 300
```

Ответ:
```json
{"detected_language": "ukrainian", "language_code": "uk", "confidence": 0.93}
```

Дёшево: модель выравнивания не задействуется, обрабатываются три
30-секундных окна. Считай 15–30 секунд на звонок.

**Как считается `confidence`.** Опрашиваются три окна — в начале, середине и
ближе к концу записи. Метрика равна средней вероятности победившего языка по
всем окнам. Она падает в двух случаях: модель не уверена (шум, музыка, тишина)
или окна разошлись между собой (в звонке звучат разные языки). Для смешанного
потока это ровно то, что нужно ловить.

Ориентир: осмысленная речь даёт 0.9+; шум без речи — около 0.4.

**Порог 0.8:**

| Условие | Что делать |
|---|---|
| `confidence >= 0.8` | язык надёжен, в этап 2 с явным `language=<код>` |
| `confidence < 0.8` | пометить `lang_uncertain`, обработать отдельной группой в конце |

## Этап 2. Расшифровка

Отсортируй очередь по `language_code` и иди группами: сначала все `uk`, потом
все `ru`, потом все `pl`. Внутри группы порядок не важен.

```bash
curl -X POST \
  "https://app.24print.ua:9443/asr?task=transcribe&language=uk&output=json&encode=true&diarize=true&min_speakers=2&max_speakers=2&auto_calculate_offset=true" \
  -H "X-API-Key: $KEY" \
  -F "audio_file=@call.mp3;type=audio/mpeg" \
  --max-time 3600 \
  -o result.json
```

Параметры — **в query string, не в form-data**:

| Параметр | Значение | Зачем |
|---|---|---|
| `language` | `uk` / `ru` / `pl` | из этапа 1. Явное указание отключает повторную детекцию — быстрее и детерминированнее |
| `diarize` | `true` | разделение по спикерам. По умолчанию `false` |
| `min_speakers`/`max_speakers` | `2` / `2` | звонок «менеджер ↔ клиент». Если неизвестно — убрать оба |
| `output` | `json` | **обязательно.** Метки спикеров есть только в JSON |
| `encode` | `true` | прогон через ffmpeg, для mp3 обязательно |
| `auto_calculate_offset` | `true` | компенсация начальной тишины в таймкодах |
| `task` | `transcribe` | `translate` переведёт на английский |

### Группа `lang_uncertain`

Вызывай `/asr` **без** параметра `language`. Сервис сам определит язык по трём
окнам и вернёт его вместе с уверенностью:

```json
{"segments": [...], "language": "pl", "language_confidence": 0.62}
```

Поле `language_confidence` присутствует только когда язык определялся
автоматически; при явно заданном `language` оно равно `null`. Записывай его
в результаты — по нему потом отбирать звонки на выборочное прослушивание.

Эта группа идёт последней, потому что языки в ней вперемешку и модель
выравнивания будет перезагружаться. При ~10% от объёма это несколько лишних
минут на весь прогон.

## Запрещённый параметр

**Никогда не передавай `initial_prompt`.** Он присутствует в схеме API, но
whisperX в этой версии его не принимает — запрос падает с `HTTP 500`.
Это известно и оставлено как есть сознательно. Доменный словарь через него
подсунуть не получится.

## Ограничения и режим работы

| Что | Значение |
|---|---|
| Одновременных внешних соединений | **3** (больше — `503`) |
| Максимальный размер файла | 1 ГБ (больше — `413`) |
| Таймаут запроса на шлюзе | 3600 с (дольше — `504`) |
| Воркеров на сервере | 4 |

Держи параллелизм **не выше 3**. Сервер параллельно обслуживает боевой поток
звонков Sales Evaluator и работает на CPU без GPU — расшифровка идёт медленнее
реального времени.

**Время.** Для 10-минутного звонка закладывай 15–40 минут. Первый запрос после
простоя дольше: воркер лениво подгружает модели. **Ретраи по таймауту не делай** —
они удваивают нагрузку на сервер, который и так занят.

**Коды ответов:**

| Код | Значение | Действие |
|---|---|---|
| `200` | успех | — |
| `401` | ключ отсутствует или неверный | проверить заголовок |
| `413` | файл больше 1 ГБ | сжать или нарезать |
| `500` | скорее всего передан `initial_prompt` | убрать параметр |
| `503` | превышен лимит соединений | подождать, повторить |
| `504` | не уложились в час | звонок слишком длинный |

## Формат результата

```json
{
  "segments": [
    {
      "start": 1.23, "end": 4.56,
      "text": "Добрий день, компанія...",
      "speaker": "SPEAKER_00",
      "words": [{"word": "Добрий", "start": 1.23, "end": 1.51, "speaker": "SPEAKER_00"}]
    }
  ],
  "language": "uk",
  "language_confidence": null
}
```

Проверка, что диаризация отработала:

```bash
python3 -c "
import json; d=json.load(open('result.json'))
print('Спикеры:', set(s.get('speaker') for s in d['segments']))
print('Язык:', d['language'], '| confidence:', d.get('language_confidence'))
"
```

Если `speaker` везде `null` — `diarize=true` не долетел. Частая причина:
параметр положили в form-data вместо query string.

## Что сервис не умеет

**Один язык на весь звонок.** Язык определяется по записи целиком и
применяется ко всей расшифровке. Разговор, где менеджер говорит по-украински,
а клиент по-польски, будет частично искажён — реплики на «чужом» языке
распознаются хуже. Низкий `confidence` как раз и служит признаком таких звонков.

Честное решение — диаризация до распознавания и расшифровка по спикерам
раздельно — требует переделки пайплайна и здесь не реализовано.
